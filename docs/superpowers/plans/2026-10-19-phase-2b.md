# Phase 2B Independent Event Verification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (recommended) to implement this plan task-by-task.

**Goal:** Add independent MAUL1 response episodes, predictor matching, verification outputs, case-study summaries, and a compact research-only dashboard section.

**Architecture:** Keep target and predictor episode logic as pure functions in `scripts/analyze.py`, emit a separate `site/data/verification.json`, and let the existing static dashboard consume that artifact without changing raw event archives or chart/replay behavior.

**Tech Stack:** Python 3.10+ standard library, unittest, static HTML/CSS/JavaScript, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-19-phase-2b-design.md`

## Global Constraints

- MAUL1 observations alone select target response episodes.
- Use a fixed 72-hour antecedent baseline with at least 48 valid hours where available.
- Use predeclared matching windows: DENL1 0–72 hours; NWCL1 0–18 hours; MDLL1 0–18 hours.
- Never treat a predictor after MAUL1 onset as advance detection.
- Never convert 00065 to NAVD88 or splice MCHL1 with USACE sources.
- Treat Sally/Beta as potentially dependent and do not count hourly records as independent samples.
- Label matches as detected timing, not validated forecast skill.

## Review Focus

- A rolling baseline must not redefine the target episode after it starts; test a fixed antecedent baseline.
- Two rises in one archive must produce two target episodes when separated by a reset, not one storm-level result.
- A missing hour must break episode continuity or downgrade its quality rather than create a false episode.
- A predictor after target onset must be unmatched/non-lead even if its anomaly is larger.
- A target with native 00065 data must not acquire NAVD88 threshold status.
