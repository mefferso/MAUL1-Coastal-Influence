# Phase 3A Historical Data Expansion and Validation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a reproducible monthly 2016–2026 archive, source/provenance validation, continuous hourly products, historical event discovery, coverage reporting, and resumable GitHub Actions execution without changing the existing event explorer datasets.

**Architecture:** Keep the current event-window acquisition and Phase 2A/2B outputs unchanged. Add focused standard-library modules: `history_sources.py` for source adapters and canonical rows, `history.py` for monthly partitions/coverage/hourly derivation, `discover.py` for independent episode discovery, and `history_validate.py` for structural/scientific checks. New artifacts live under `site/data/history/` and are independently indexed.

**Tech Stack:** Python 3.10+ standard library, gzip JSON, urllib, unittest, static HTML/CSS/JavaScript, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-19-phase-3a-design.md`

## Global Constraints

- Preserve all existing event archives, hourly event products, `analysis.json`, `verification.json`, charts, replay, map, and Phase 2A/2B semantics.
- Target UTC months 2016-01 through 2026-12; use half-open month intervals and source-compatible monthly requests.
- Never fabricate, interpolate, silently retry into a different source, or merge MCHL1 with USACE 85420/85420LA.
- Keep MAUL1 00065 gage height separate from direct 63160 NAVD88; never apply the modern −1.38-ft conversion.
- NDBC is an independent comparison source and never fills CO-OPS automatically.
- Discovery outputs are descriptive research records, not causal classifications, forecasts, probabilities, or verified prediction skill.
- Use only free GitHub Actions/Pages and Python standard-library dependencies.
- Existing successful partitions are immutable unless `--refresh` is explicitly supplied.

## Review Focus

- A failed/403 source response must produce a manifest failure record and zero fabricated rows; test source failures and resume behavior in Task 2.
- A month boundary must not lose a trailing statistic or leak a future observation into the target month; test partition bounds and hourly derivation in Task 3.
- A unit/datum/station identity change must be reported and must not be normalized away; test quality validation and provenance separation in Task 3.
- Wind direction wraparound and CO-OPS/NDBC disagreement must be compared circularly without averaging sources; test comparison fixtures in Task 3.
- Overlapping river/coastal episodes and quiet/nonresponse controls must be retained without automatic causal labels; test discovery deduplication and controls in Task 4.
