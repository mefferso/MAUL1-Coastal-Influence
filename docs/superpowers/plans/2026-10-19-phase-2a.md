# Phase 2A Historical Corrections and Event-Onset Analysis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (recommended) to implement this plan task-by-task.

**Goal:** Add provenance-safe historical retrieval, scientific hourly products, experimental onset diagnostics, and a research-only website section.

**Architecture:** Keep acquisition in `scripts/build.py`, derived products and onset detection in `scripts/analyze.py`, and presentation in the existing static site. Preserve raw observations and emit derived records/metadata alongside them.

**Tech Stack:** Python 3.10+ standard library, unittest, static HTML/CSS/JavaScript, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-19-phase-2a-design.md`

## Global Constraints

- Never globally apply the −1.38-ft MAUL1 offset.
- Only direct MAUL1 63160 observations qualify for the 4.0-ft NAVD88 threshold.
- Do not interpolate missing observations.
- Never use future observations in an onset signal.
- Keep MCHL1, USACE 85420, and 85420LA separate unless authoritative compatibility is established.
- Legacy optimized correlations are diagnostics, not propagation or forecast lead times.

## Review Focus

- A source can be queried successfully but return no historical records; preserve that distinction in provenance and test it.
- A datum change must prevent cross-datum change calculations and threshold marking.
- A missing hour must remain missing and must not enable a trailing signal.
- A candidate onset must not change when future rows are appended.
- Overlapping event windows must be documented as dependent episodes.
