# Phase 6 operations

The `Phase 6 prospective verification` workflow runs hourly at minute 17 UTC. GitHub may delay a scheduled run; each record stores nominal slot, feature anchor, and actual issue time separately. Future issue valid times follow the Phase 5 contract: completed-hour feature anchor plus horizon; effective lead is valid time minus actual issue time. `workflow_dispatch` defaults to an isolated simulation; choose `authentic` only to make a real current-time issue. Pull requests run the regression suite, full frozen holdout replay, a hosted-runner live provider check, and both site smoke checks.

The workflow uses only GitHub-hosted runners and free Pages deployment. A serialized concurrency group protects the single writer. Each issuance, raw-normalized source snapshot, attempt audit, observation capture, and verification revision uses a create-only archive path. The commit step fetches and rebases up to three times to accommodate concurrent updates. Actions artifacts are retained for 90 days; committed archives remain available with the repository.

USGS NWIS supplies MAUL1 (07380215), DENL1 (07378500), and MDLL1 (301200090072400). NOAA CO-OPS 8761927 supplies NWCL1 water levels, water-level predictions captured during the issue cycle, and wind. HADS live delivery for MCHL1 has not yet been established by the available public endpoint; MCHL1 is explicitly reported unavailable until a verified current feed is configured. USACE 85420/85420LA are never substituted. MAUL1 00065 remains native gage height and 63160 NAVD88 remains excluded from model features.

All source rows preserve source identity, parameter, units, datum, observation time, capture time, QC, URL, and response hash. Only observations falling in completed UTC hours enter the Phase 5 feature builder. There is no interpolation or carry-forward. Model-specific missing inputs are imputed only by the frozen Phase 5 transformation, and the record reports the number imputed. The 80% interval widths are the existing frozen historical widths; Phase 6 does not recalibrate them.

The independent verification fetch occurs after issue cycles. It uses subsequent MAUL1 native observations within 30 minutes of each forecast valid time and records both forecast valid time and the actual observation valid time. Verification waits until the valid time and observation capture have passed. Reprocessing the same value is idempotent; changed late values create a new numbered immutable revision. Performance files summarize the accumulated prospective records only. Event-level skill is withheld until five independent event groups exist.

If a run fails, inspect the run log and its uploaded `phase6-cycle-*` artifact. A source outage is retained as source status and results in model abstention where the target is stale or missing. Failed workflow runs do not create a successful deployment; rerun only after confirming the source or repository cause. A scheduled delay must never be interpreted as an earlier authentic issuance. All outputs remain research-only and do not establish operational skill or datum equivalence to NAVD88 flood thresholds.

## Phase 6.2 hourly feature diagnostics

The authentic issue snapshot, attempt audit and compact latest-dashboard record now include `feature_diagnostics`, with the exact UTC model feature anchor, expected latest completed hourly bin, actual latest eligible bin for each network input, and missing feature names grouped by coastal, river and target. A successful NWCL1 HTTP retrieval or station-level age check **does not** guarantee the latest required hourly bin exists. Missing water/prediction pairings must not be manufactured, relabeled or time-shifted to inflate coastal feature availability. Model imputations remain visible as a separate diagnostic. Check the first post-change real issuance before concluding that coastal predictors are functioning at intended coverage.

## Phase 6.4 source archive format

Future authentic forecast issuances use `phase6.forecast.v2`: a compact create-only JSON issue with frozen model predictions, issue-time derived features, eligibility and diagnostics, plus a SHA-256 reference to losslessly gzip-compressed issue-time source observations stored in `archive/snapshots/<sha256>.json.gz`. This compressed payload retains original normalized observations, timestamps, units, datums, QC, source URLs and response hashes. `recover_source_snapshot` verifies its checksum before returning data. The write operation is create-only and rejects an existing issue file. Previously issued v1 JSON snapshots are unchanged and remain readable in the same verification history; verification does not require expanding evidence snapshots. This reduces Git and Pages transfer size, but does not alone solve the long-term limits of committing hourly archives to Git.
